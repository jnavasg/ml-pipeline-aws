LINEA DE TIEMPO DETALLADA -- VARIANTE A (REST / z/OS Connect EE)
=====================================================================

1) [APP] El usuario pide el saldo
   Toca "Consultar saldo" en la app. Ya tiene el numero de cliente
   guardado en la sesion.

2) [APP] Se arma la peticion REST
   GET /clientes/0001234567
   La app no sabe que hay COBOL detras -- para ella es un endpoint
   HTTP normal.

3) [PUENTE - z/OS Connect EE] Llega al traductor
   z/OS Connect EE recibe el GET y arma el COMMAREA binario a partir
   del mapeo campo-a-campo del copybook.

4) [PUENTE] Se invoca el programa
   EXEC CICS LINK PROGRAM('CONSCLI') COMMAREA(area)
   Identico a lo que haria una pantalla 3270 hace 30 anios.

5) [COBOL-CICS] CONSCLI hace su trabajo
   EXEC CICS READ contra el VSAM CLIENTES, arma la respuesta y hace
   EXEC CICS RETURN. Fin de su responsabilidad.

6) [PUENTE] Se traduce la salida
   El COMMAREA de salida se convierte a JSON segun el mismo mapeo
   (offset -> campo).

7) [APP] La respuesta viaja de vuelta
   { "nombre": "JUAN PEREZ GOMEZ", "saldo": 15340.50, "status": "00" }

8) [APP] Se muestra el resultado
   La app pinta "Saldo: $15,340.50". El usuario nunca se entera del
   programa de 1996 que hizo el trabajo real.

=====================================================================
LINEA DE TIEMPO DETALLADA -- VARIANTE B (SOAP / CICS Web Services)
=====================================================================

1) [APP] El usuario pide la consulta
   Desde el portal web, solicita los datos del cliente.

2) [APP] Se arma la peticion SOAP
   POST ConsultaClienteService con el XML en el cuerpo. El portal
   solo habla SOAP, no sabe de CICS.

3) [PUENTE - Pipeline CICS] Llega al pipeline SOAP
   Valida el XML contra el XSD del WSDL (generado con DFHLS2WS) y
   arma el COMMAREA.

4) [PUENTE] Se invoca el programa
   EXEC CICS LINK PROGRAM('CONSCLI') COMMAREA(area)
   El mismo LINK que en la variante REST.

5) [COBOL-CICS] CONSCLI hace su trabajo
   EXEC CICS READ contra el VSAM CLIENTES, arma la respuesta y hace
   EXEC CICS RETURN. El programa es exactamente el mismo que en la
   variante A.

6) [PUENTE] Se traduce la salida
   El COMMAREA de salida se envuelve en el XML de respuesta,
   validado contra el mismo XSD.

7) [APP] La respuesta viaja de vuelta
   <ConsultaClienteResponse>
     <nombre>JUAN PEREZ GOMEZ</nombre>
     <saldo>15340.50</saldo>
     <status>00</status>
   </ConsultaClienteResponse>

8) [APP] Se muestra el resultado
   El portal parsea el XML y pinta el saldo en pantalla.
